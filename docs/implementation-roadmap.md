# Implementation Roadmap

**Status:** PROPOSED. Each phase ends in a working, testable state, and a phase isn't "done" until its acceptance tests pass in CI.

| Phase | Scope                                                                                                                                                                                                                           | Acceptance (must pass)                                                                             |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 1     | Research, tech decisions, architecture, roadmap (this set) → **owner approval** → written design spec → detailed implementation plan                                                                                            | Owner approves spec + plan                                                                         |
| 2     | Monorepo, TS strict, lint/format, CI, env config + validation, design-system foundation, ports + in-memory fakes, port contract-test harness, logging/error model, Sentry wiring. **Spike:** Hono + Mongo on Cloudflare Workers | CI green; `pnpm dev` runs web + api; contract tests pass on fakes; spike verdict recorded          |
| 3     | Mongo adapters + migrations, Better Auth, users/workspaces/memberships, RBAC policy, tenant context, Super Admin seed, audit log                                                                                                | Tenant-isolation suite (scenarios 1, 2), auth tests, transaction tests on an in-memory replica set |
| 4     | Restaurants, branches, hours, tax & ordering rules, staff invites/roles, tables, QR generate/revoke/regenerate                                                                                                                  | Scenarios 3, 4, 11; QR tokens are hashed and contain no IDs                                        |
| 5     | Menu (categories, items, variants, modifiers, images, availability) + customer QR ordering, table sessions                                                                                                                      | Price snapshot tests; scenario 12 (concurrency); E2E customer flow                                 |
| 6     | Waiter dashboard, KDS, realtime (Ably adapter + polling fallback), push + in-app notifications                                                                                                                                  | Scenario 8; E2E waiter → kitchen flow                                                              |
| 7     | Bills, counter payment recording, reconciliation                                                                                                                                                                                | Scenarios 9, 10; transaction-safety tests                                                          |
| 8     | Offline persistence + sync engine (outbox, retry, conflicts, manual sync, status UI)                                                                                                                                            | Scenario 7; interrupted-sync recovery tests                                                        |
| 9     | Plans, trials, entitlements, grace/read-only, reminders, export, cron worker                                                                                                                                                    | Scenarios 5, 6; entitlement tests                                                                  |
| 10    | Super Admin dashboard (metrics, plans, manual activation, trial extension, audit)                                                                                                                                               | Admin authorization tests (server-verified only)                                                   |
| 11    | Security review, performance, backups/restore drill, deployment docs, full E2E                                                                                                                                                  | All 12 scenarios + E2E green; restore drill done                                                   |

Parallel work (multiple agents) starts in Phase 4, once `packages/contracts` and `packages/core/ports` are frozen for that phase. Each agent owns one module directory.
