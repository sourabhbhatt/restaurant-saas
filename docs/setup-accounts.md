# Accounts and services (owner)

The accounts RestaurantOS uses today, what each is for and where the setup steps live. You create and own them, because they are tied to your identity and billing. Use one e-mail for all of them.

**Never paste secrets (passwords, API keys, connection strings) into chat, tickets or code.** Server secrets live in Google Secret Manager; local ones in `.env.local` (git-ignored). Random values such as `APP_SECRET`, `CRON_SECRET` and `PROXY_SHARED_SECRET` are generated (`openssl rand -hex 32`), not chosen.

The step-by-step list of what is still to do, with priorities and costs, is in [launch/manual-actions-required.md](launch/manual-actions-required.md).

## Environments

- **Local:** your machine; a local PostgreSQL 18 or PGlite under `.data/`; nothing touches Google Cloud. Tests and the browser E2E suite use their own throwaway databases.
- **Staging:** the Google Cloud project above, for personal testing. Cloud SQL is stopped when you are not testing (`infra/gcp/staging.sh start` / `stop`); a guard job stops it if it is left running.
- **Production:** not provisioned. It needs its own Google Cloud project, identity provider, secrets and domain; the production deploy workflow refuses to run until then ([runbooks/ci-cd.md](runbooks/ci-cd.md)).
